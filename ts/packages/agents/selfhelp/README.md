# @typeagent/selfhelp-agent

The TypeAgent **Help** agent. It answers questions about TypeAgent itself:

- **Find a command** - the `@`-command and equivalent natural-language phrasing
  for what you want to do ("what's the command for X", "how do I X", "can I X").
- **Explain TypeAgent** - what it is, what it can do overall, and how to set it
  up ("what is TypeAgent?", "how do I configure API keys?").

(Describing a specific named agent - "what can the browser agent do" - is handled
by the built-in `describe` in the dispatcher; a deferred `describeAgent` action
here is commented out to avoid overlapping it. See the TODO in
`src/selfHelpSchema.ts`.)

It ships enabled by default. Ask in natural language (no `@` prefix), for
example:

- "what's the command to create a new conversation?"
- "what is TypeAgent and what can it do?"

or invoke it explicitly:

```
@selfhelp create a new conversation
@selfhelp about what is TypeAgent
```

A command-lookup answer shows both ways to do it - the `@`-command and the
phrasing you can just say:

- `@conversation new [<name>]` — Create a new conversation, optionally with a name
  or say: "start a new conversation", "new conversation called design review"

## Relationship to `@help`

This agent does **not** replace the built-in `@help` command. `@help` is the
deterministic command reference (usage, arguments, and flags). The Help agent
maps a natural-language intent to the matching command(s)/action(s) and explains
them.

## How it works

The agent routes a question to one of two actions (`src/selfHelpSchema.ts`):
`answerTypeAgentQuestion` (command lookup / "can I X") and `explainTypeAgent`
(conceptual + setup). Each is grounded on bundled data - nothing is fetched at
runtime - and answered via **TypeChat** so the model can only use what it is
given.

**Command lookup** is grounded on the **Action Browser catalog**
(`action-browser.json`), which lists every agent action (with example phrasings)
and every `@`-command, including the explicit command→action links (e.g.
`@conversation new` ↔ the `newConversation` action). The catalog is generated by
`@typeagent/action-browser` as part of the docs build and copied into `dist/` at
build time (see `scripts/copyCatalog.mjs`).

For a command-lookup question, the handler (`src/selfHelpActionHandler.ts`):

1. selects the relevant slice of the catalog (`src/catalog.ts`), keeping each
   command together with its linked action;
2. asks the model to pick the matching capability as a typed
   `CommandHelpResponse` (`src/commandHelpResponseSchema.ts`) - using only entries
   from the catalog;
3. renders the result to Markdown (`src/render.ts`), resolving each command's
   usage and its paired phrasings from the catalog so the output stays grounded.

(A deferred `describeAgent` action would reuse the same shape scoped to one agent
via `findAgent`/`groupForAgent`; it is commented out because the dispatcher's
built-in `describe` already covers it. Those catalog helpers remain, exported and
tested, for a future pass that may combine the two.)

**Explaining TypeAgent** is grounded on the conceptual/setup docs (the
`docs/overview` markdown plus the workspace `README.md`), also copied into
`dist/docs/` at build time. `src/docs.ts` splits them into heading-delimited
chunks and selects the ones most relevant to the question, always including the
overview intro so "what is TypeAgent" is answered even when no keyword matches;
the model returns a typed `ExplainResponse` (`src/explainResponseSchema.ts`).

Because the command→action links and docs are read from bundled data, more
capabilities light up automatically as they are annotated or documented - no
changes needed here.

## Build & test

```
pnpm --filter @typeagent/selfhelp-agent build
pnpm --filter @typeagent/selfhelp-agent test
```

Build compiles the handler (`tsc`), the routing action schema
(`asc` -> `dist/selfHelpSchema.pas.json`), and copies the catalog and the
conceptual docs into `dist/`.
