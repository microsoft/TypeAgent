# @typeagent/selfhelp

The TypeAgent **help** grounding library. It answers questions about TypeAgent
itself - command lookup, capability checks, and conceptual/setup topics - in a
single call, and is consumed by the dispatcher's built-in **`system.help`**
schema. It is a library, not a registered agent (there is no `@selfhelp`
command); the user-facing entry point is `system.help` in
`@typeagent/agent-dispatcher`.

## What it does

`runHelp(question, context)` (exported from `./help`) returns a structured answer
for any question about TypeAgent, for example:

- "what's the command to create a new conversation?" (command lookup)
- "can I play music with TypeAgent?" (capability check)
- "what is TypeAgent and what can it do?" (concept)
- "what keys do I need to run it?" (setup)

The answer is a summary plus, when relevant, command cards (the `@`-command and
the natural-language phrasing you can just say) and supporting detail/pointers.

## How it works

`runHelp` grounds a single **TypeChat** call on two bundled sources - nothing is
fetched at runtime - and the model may only use what it is given:

- **The Action Browser catalog** (`action-browser.json`) lists every agent
  action (with example phrasings) and every `@`-command, including the explicit
  command→action links (e.g. `@conversation new` ↔ the `newConversation`
  action). It is generated by `@typeagent/action-browser` as part of the docs
  build and copied into `dist/` at build time (see `scripts/copyCatalog.mjs`).
  `src/catalog.ts` selects the relevant slice for the question.
- **The overview docs** (the `docs/overview` markdown plus the workspace
  `README.md`), also copied into `dist/docs/` at build time. `src/docs.ts` splits
  them into heading-delimited chunks and selects the most relevant, always
  including the overview intro so "what is TypeAgent" is answered even when no
  keyword matches.

The model returns a typed `HelpResponse` (`src/helpResponseSchema.ts`), which
`src/render.ts` turns into display blocks (summary, command cards, detail
bullets, and "See also" pointers), resolving command usage and phrasings from the
catalog so the output stays grounded.

Describing a specific installed agent ("what can the browser agent do") is
**not** handled here - the dispatcher's live `describe` engine owns that. When
`system.help` gets a describe request for something that isn't a real agent, it
falls back to `runHelp`.

Because the catalog and docs are read from bundled data, more capabilities light
up automatically as they are annotated or documented - no changes needed here.

## Build & test

```
pnpm --filter @typeagent/selfhelp build
pnpm --filter @typeagent/selfhelp test
```

Build compiles the library (`tsc`) and copies the catalog and the conceptual
docs into `dist/`.
